# VIT Pune Campus Explorer

A student-built, static guide to VIT Pune clubs, recruitment deadlines and academic windows. Plain HTML, CSS and vanilla JavaScript. No build step, no backend, no API keys, no environment variables.

> Not an official VIT Pune site. Verify anything important at https://www.vit.edu

## Repository layout (upload exactly like this, all at the repo root unless shown)

```
index.html          page structure
style.css           all visuals (dark + light themes)
script.js           search, filters, plan, quiz, registration form, import
tracker.js          recruitment deadlines + academic calendar (Asia/Kolkata)
data.js             clubs, events, resources, places, FAQ, config (edit your name/links here)
data-extra.js       optional place to add more data without touching data.js
data-verified.js    evidence pack: verified clubs, deadlines, academic windows, known gaps
sw.js               service worker (offline cache)
manifest.json       installable-app metadata
icon.svg            icon (vector)
icon-192.png        icon (binary, keep)
icon-512.png        icon (binary, keep)
.gitignore
package.json        dev-only: scripts + test dependency (the site itself has none)
package-lock.json   generated by npm; do not edit by hand
tests/smoke.test.js automated smoke tests
docs/SCOPE.md       brief-to-implementation map, enhancements vs disabled
docs/EXTRAS.md      audit of the quiz, PWA and import
docs/INTERVIEW_GUIDE.md  how to present and defend the project
README.md
```
Do **not** upload `preview-all-in-one.html` (a preview-only copy; it is in `.gitignore`).
`data-verified.js` and `tracker.js` are required. Without them the deadlines and calendar sections stay empty.

## Before you publish
1. In `data.js` → `config`: set `author`, `linkedin`. The GitHub and live-site URLs assume the repo is named `vit-pune-campus-explorer` under `prathmeshwinedeshkar-dev`; change them if not. A link still containing `your-` is hidden automatically.
2. Re-verify any detail you present. Items without a source are shown as **Unverified**.

## Deploy on GitHub Pages
1. Create a public repo `vit-pune-campus-explorer` and upload every file above, keeping `tests/smoke.test.js` inside `tests/`.
2. Settings → Pages → Source: *Deploy from a branch* → `main` / `(root)` → Save.
3. After about a minute the site is at `https://<username>.github.io/vit-pune-campus-explorer/`.
Pushing the code is not the same as being deployed: confirm the live URL loads and the browser console is clean.

## Updating safely
- The service worker is network-first: online visitors always get new files, and offline visitors get the last cached copy. Bump `CACHE` in `sw.js` (`vit-explorer-v6` → `v7`) only to purge old caches after a big change.
- Feature switches: `config.features` in `data.js` (`quiz`, `pwa`, `import`; import is off by default). See `docs/EXTRAS.md`.
- Add data in `data-extra.js` (`CampusData.add("clubs", [...])`) or, if you switch `features.import` on, via the Import button (JSON with `clubs`, `events`, `resources`, `places`; items need a string `id` and `name`; max 200 KB). Imports are stored in that visitor's browser only and are always labelled Unverified.
- Never fill an unknown value with a guess. Leave it blank and it will show as unverified.

## Data rules the site follows
- Recruitment: dates and times in Asia/Kolkata; closed deadlines never show as open; no closing time is inferred.
- Calendar: FY, SY, TY, Final Year and Direct Second Year SEDA are kept separate; exams are windows, not subject timetables; FY has no verified dates yet and says so.
- Registration form: saves to the visitor's device only and registers nobody.
- Club leads are shown as listed on the source page when checked; tenure is not confirmed.

## Checks
```
npm ci
npm run check    # syntax check of every JS file
npm test         # 58 tests in jsdom (flags on/off, GDG data, hostile import, service-worker strategy), clock fixed to 30 Oct 2026 IST
```
Tests do **not** cover real browsers, phone layouts, Lighthouse, screen readers or installing the app.

## Known limits
Static data goes stale; the offline cache needs the version bump above; sample testimonials are fictional and labelled; PRN validation uses a loose pattern (`prnPattern` in `data.js`).
